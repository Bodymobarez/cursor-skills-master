# Cloudflare Platform — Complete (Workers + the edge data plane)

**Mandate:** Workers run V8 isolates at the edge — milliseconds of CPU, no Node by default, and **every
resource is a binding** declared in `wrangler.jsonc`. Wire bindings (not SDK clients), pick the right
storage primitive (KV vs D1 vs R2 vs DO) for the consistency you need, keep `compatibility_date` current,
and `wrangler types` after every config change. Edge isn't a small server — it's a different runtime.

## When to use / when NOT to use
- **Use** for globally low-latency APIs/edge logic, static+SSR sites (Pages), object storage with **zero
  egress fees** (R2), edge KV config/cache, edge-local SQL (D1), strongly-consistent coordination /
  websockets / per-entity state (Durable Objects), and async fan-out (Queues).
- **NOT** for long CPU-bound jobs beyond the 5-min cap, full POSIX/Node servers, or large relational
  workloads (D1 caps at 10 GB — use Neon/Postgres via Hyperdrive instead → `neon-postgres-serverless`).
  Don't port a stateful Express app 1:1; rearchitect around isolates + bindings.

## Mental model
A Worker is a **stateless isolate** spun up per request near the user — no filesystem, no persistent memory,
Web-standard APIs (`fetch`, `crypto`, `Request`/`Response`). State lives in **bindings**: KV (eventually
consistent global cache), D1 (SQLite, regional + edge read replicas), R2 (S3-compatible objects, free
egress), Durable Objects (single-threaded, strongly-consistent per-id actor + storage), Queues (async).
You never instantiate an "AWS client" — you declare a binding and call `env.MY_THING`.

## 1. Project + `wrangler.jsonc` (JSON config is the 2026 default)

```bash
npm create cloudflare@latest my-worker     # C3 scaffolder (Wrangler v4)
# wrangler is the CLI: dev, deploy, secret, tail, d1, r2, kv, queues...
```

```jsonc
// wrangler.jsonc — bindings are NOT inheritable; redeclare per env. Keep compatibility_date fresh.
{
  "$schema": "./node_modules/wrangler/config-schema.json",
  "name": "my-worker",
  "main": "src/index.ts",
  "compatibility_date": "2026-06-02",          // set to "today"; pins runtime behavior
  "compatibility_flags": ["nodejs_compat"],     // enables Buffer/crypto/util subset when needed
  "observability": { "enabled": true },         // turn on Workers Logs/metrics
  "vars": { "ENVIRONMENT": "production" },       // NON-secret config only

  "kv_namespaces": [ { "binding": "KV", "id": "<KV_ID>" } ],
  "r2_buckets":    [ { "binding": "BUCKET", "bucket_name": "uploads" } ],
  "d1_databases":  [ { "binding": "DB", "database_name": "app", "database_id": "<D1_ID>" } ],
  "durable_objects": { "bindings": [ { "name": "ROOM", "class_name": "ChatRoom" } ] },
  "migrations": [ { "tag": "v1", "new_sqlite_classes": ["ChatRoom"] } ], // DO classes need a migration
  "queues": {
    "producers": [ { "binding": "JOBS", "queue": "jobs" } ],
    "consumers": [ { "queue": "jobs", "max_batch_size": 10, "max_retries": 3, "dead_letter_queue": "jobs-dlq" } ]
  },
  "triggers": { "crons": ["0 * * * *"] },

  "env": {
    "staging": { "name": "my-worker-staging", "vars": { "ENVIRONMENT": "staging" },
      "kv_namespaces": [ { "binding": "KV", "id": "<STAGING_KV_ID>" } ] }
  }
}
```

```bash
wrangler types        # AFTER any binding change → generates the Env interface for TS (run it every time)
wrangler dev          # local dev; bindings simulated locally (.wrangler/state) unless remote:true
wrangler deploy       # ship; `--env staging` for the staging environment
```

```ts
// worker-configuration.d.ts is generated by `wrangler types`; consume the typed env:
export default {
  async fetch(req: Request, env: Env, ctx: ExecutionContext): Promise<Response> {
    ctx.waitUntil(logAsync(req));                 // do work after the response is sent
    const cached = await env.KV.get("config", "json");
    return Response.json({ env: env.ENVIRONMENT, cached });
  },
} satisfies ExportedHandler<Env>;
```

## 2. Storage primitives — pick by consistency (the decision that matters)

| Primitive | Model | Consistency | Best for | Hard limits |
|---|---|---|---|---|
| **KV** | global key-value | **eventual** (~secs to propagate) | read-heavy config, cache, feature flags, sessions | value ≤ 25 MiB; not for "read-your-write" |
| **D1** | SQLite (SQL) | strong (single primary) + edge **read replicas** | relational app data, small/medium | 10 GB/db (paid), 500 MB (free); row ≤ 2 MB |
| **R2** | object store (S3 API) | strong per-object | files, media, backups, data lake | **$0 egress**; multipart for big objects |
| **Durable Objects** | per-id actor + storage | **strong, single-threaded** | coordination, websockets, counters, rate limits, per-room/per-user state | one instance per id (the consistency boundary) |
| **Queues** | message queue | at-least-once | async jobs, decoupling, retries, DLQ | batch + retry config in wrangler |

```ts
// D1 — ALWAYS use bound parameters (.bind), never string-concat SQL (injection + no plan cache)
const { results } = await env.DB.prepare(
  "SELECT id, email FROM users WHERE org_id = ?1 ORDER BY created_at DESC LIMIT ?2"
).bind(orgId, 20).all();
await env.DB.batch([                              // batch = one round trip, transactional
  env.DB.prepare("INSERT INTO audit(actor, action) VALUES (?1, ?2)").bind(uid, "login"),
  env.DB.prepare("UPDATE users SET last_seen = ?1 WHERE id = ?2").bind(Date.now(), uid),
]);
```
```bash
wrangler d1 create app
wrangler d1 migrations create app create_users   # writes migrations/ SQL
wrangler d1 migrations apply app --remote         # apply to prod (omit --remote for local)
```

```ts
// R2 — S3-compatible, free egress. Stream large bodies; don't buffer in the isolate (128 MB RAM cap).
await env.BUCKET.put(`u/${id}.png`, req.body, { httpMetadata: { contentType: "image/png" } });
const obj = await env.BUCKET.get(`u/${id}.png`);
return obj ? new Response(obj.body, { headers: { etag: obj.httpEtag } }) : new Response("404", { status: 404 });
```

```ts
// Durable Object — single-threaded, strongly consistent per id. The right home for a counter/rate-limiter.
export class ChatRoom {
  constructor(private state: DurableObjectState, private env: Env) {}
  async fetch(req: Request) {
    let n = (await this.state.storage.get<number>("count")) ?? 0;
    await this.state.storage.put("count", ++n);    // serialized — no race across concurrent requests
    return Response.json({ count: n });
  }
}
// route to a specific instance: const id = env.ROOM.idFromName(roomName); env.ROOM.get(id).fetch(req)
```

```ts
// Queues — producer + consumer in the same or different Worker; ack/retry per message; DLQ for poison msgs
export default {
  async fetch(req: Request, env: Env) { await env.JOBS.send({ userId: "u1", type: "welcome" }); return new Response("queued"); },
  async queue(batch: MessageBatch, env: Env) {
    for (const m of batch.messages) {
      try { await handle(m.body); m.ack(); }
      catch { m.retry(); }                          // exhausted retries → dead_letter_queue
    }
  },
} satisfies ExportedHandler<Env>;
```

**Pages** for sites: `wrangler pages deploy ./dist` (or Git integration); Pages Functions share the same
bindings model. Use Pages for the frontend, Workers for APIs (or a single Worker with static assets).

## 3. Secrets vs vars (don't mix them)
```bash
wrangler secret put STRIPE_KEY        # encrypted, NOT in wrangler.jsonc, accessed as env.STRIPE_KEY
wrangler secret list
# Local dev secrets go in .dev.vars (gitignored). `vars` in wrangler.jsonc are NON-secret config only.
```
Never put API keys in `vars` (they're plaintext in config + dashboard). Secrets are write-only and injected
at runtime. For >Worker-scoped secrets, use **Secrets Store** bindings.

## 4. DNS, WAF, CDN/cache (the network layer)
- **DNS:** Cloudflare authoritative DNS; a record **proxied** (orange cloud) routes through Cloudflare's
  edge (CDN/WAF/cache) — **grey cloud = DNS only**, you lose all protection/caching. Manage via dashboard,
  API, or Terraform (`cloudflare_record`).
- **Cache:** edge caches by Cache Rules; control with `Cache-Control` + `cf` fetch options. Use the **Cache
  API** in Workers for custom keys. Purge by URL/tag/everything via API on deploy.
- **WAF:** managed rulesets (OWASP), custom rules (block/challenge by path/geo/ASN/header), **rate limiting
  rules**, bot management. Put auth/admin paths behind stricter rules.
- **TLS:** universal SSL by default; use Full (strict) to origin; enable HSTS, min TLS 1.2+.

```ts
// Read-through cache pattern at the edge using the Cache API
const cache = caches.default;
let res = await cache.match(req);
if (!res) {
  res = await fetch(originReq);
  res = new Response(res.body, res);
  res.headers.set("Cache-Control", "public, max-age=300");
  ctx.waitUntil(cache.put(req, res.clone()));
}
return res;
```

## 5. Observability — `wrangler tail` + Workers Logs
```bash
wrangler tail my-worker --format pretty                 # live prod logs (real traffic)
wrangler tail my-worker --status error --search "5xx"   # filter to errors
wrangler deployments list && wrangler rollback           # see versions; instant rollback on a bad deploy
wrangler check startup                                   # measure startup time vs the 1s limit
```
Turn on `"observability": { "enabled": true }` for Workers Logs (queryable) + analytics. Emit structured
`console.log(JSON.stringify(...))` with a request id. Tail Workers don't sample at low volume; sample at high
volume. Watch CPU-time, error rate, and (for DO/D1) storage growth.

## 6. Real platform limits (know these before you design)

| Limit | Free | Paid |
|---|---|---|
| Requests | 100k/day | unlimited |
| **CPU time / request** | 10 ms | **default 30 s, up to 5 min** (`"limits": { "cpu_ms": 300000 }`) |
| Memory | 128 MB | 128 MB |
| Subrequests/request | 50 | 1,000 (50 default per binding type aside) |
| Worker size (gzipped) | 3 MB | 10 MB |
| Startup time | 1 s | 1 s |
| **KV value size** | 25 MiB | 25 MiB |
| **D1 db size** | 500 MB | 10 GB |
| Cron wall time | — | 15 min (Cron/Queue consumer) |

Wall-clock time (waiting on `fetch`/subrequests) is effectively unlimited; **CPU** time is what's capped.
Memory is 128 MB — **stream** R2/large bodies, never buffer them.

## Edge cases & war stories
- **`env.BINDING` is undefined.** Name mismatch/case, or `wrangler dev` not restarted after editing config
  (it doesn't hot-reload config). Binding names are exact: `"binding": "KV"` → `env.KV`.
- **KV "read-your-write" bug.** A user writes then immediately reads stale data — KV is eventually
  consistent (seconds). Use D1/DO for read-your-write; KV for tolerant-of-staleness reads.
- **`Could not resolve node:...` on deploy.** Code/dep uses Node APIs → add `compatibility_flags:
  ["nodejs_compat"]` (or swap to a Web API).
- **D1 local vs remote divergence.** `wrangler dev` uses a local SQLite file; prod is separate. Apply
  migrations with `--remote`; data inserted locally never reaches prod.
- **CPU timeout on heavy work.** Default 30 s cap; raise `cpu_ms` to ≤300000, offload to a DO/Queue, or chunk.
- **Buffering a big R2 object → OOM** (128 MB). Stream the body through; use multipart upload for big files.
- **Durable Object hot single instance.** All traffic to one `idFromName` serializes on one isolate — shard
  by a composite id if a single DO becomes a bottleneck.
- **Grey-cloud DNS** accidentally bypasses WAF/cache — confirm the record is **proxied** for protected hosts.

## Performance
- KV for hot read-mostly data (cache at edge). D1 `.batch()` to cut round trips; index your SQL. Cache API +
  `Cache-Control` for origin offload. Keep bundles small (faster cold isolate start). `ctx.waitUntil` for
  fire-and-forget. D1 read replicas for global read latency.

## Security
- Secrets via `wrangler secret`/Secrets Store, never `vars`. Validate input (`zod`) at the edge. WAF +
  rate-limiting rules on auth/admin paths. Scope API tokens least-privilege; rotate. mTLS to origin where
  needed; verify webhook signatures inside the Worker.

## Scale & reliability
- Workers scale automatically/globally. Queues + DLQ for async resilience and backpressure. DO for
  per-entity consistency; shard hot DOs. D1 has PITR (Time Travel, 30-day paid). Versioned deploys +
  `wrangler rollback` for instant recovery; gradual deployments for canary.

## Testing
- `@cloudflare/vitest-pool-workers` runs tests **inside the Workers runtime** with real bindings (Miniflare).
  Test D1 against a local migrated DB; assert queue consumer ack/retry. `wrangler dev --remote` to hit real
  resources when local simulation diverges.

## Observability
- `observability.enabled`, `wrangler tail`, Workers Logs + Analytics, Logpush to your sink. Alert on CPU,
  errors, DO/D1 storage. Structured logs + request id.

## Cost notes
- Paid plan $5/mo min; requests + CPU-ms metered (30M CPU-ms included). **R2 has $0 egress** (its headline
  advantage over S3). KV/D1/DO/Queues each metered (reads/writes/storage/operations). Free tier is generous
  for prototypes; model row-reads (D1) and KV operations at scale.

## Anti-patterns
- Treating a Worker like a Node server (filesystem, long CPU, in-memory state across requests).
- KV where you need read-your-write/strong consistency (use D1/DO).
- Secrets in `vars`/`wrangler.jsonc`. Forgetting `wrangler types` after a binding change.
- Buffering large R2 objects in memory. String-concatenated D1 SQL. Grey-cloud on protected hosts.
- One Durable Object id for everything (serialized hotspot).

## Agent checklist
```
- [ ] wrangler.jsonc with current compatibility_date + nodejs_compat (only if needed); observability on
- [ ] Every resource is a binding; `wrangler types` run after each config change; typed Env consumed
- [ ] Storage primitive matches consistency need (KV eventual / D1 strong / R2 objects / DO per-id strong)
- [ ] D1 uses .bind() params + .batch(); migrations applied with --remote
- [ ] R2 bodies streamed (no buffering); large files multipart
- [ ] Durable Objects declared with a migration; hot ids sharded
- [ ] Queues consumer ack/retry + dead_letter_queue configured
- [ ] Secrets via `wrangler secret`/Secrets Store; .dev.vars gitignored; never in vars
```
